Development notes · Stage 56

Stage 56 – ROMF8/ROMC0 source-first power-on: The original RAM3/RAM7 test pattern is written into the source-format video framebuffer using RESET1 colours. The diagnostic success screen uses ROMC0.RORAOK text and positions, then ROMF8.GAMEOV. POWER ON unlocks Web Audio and issues the QUASAR sound command. The ROM checksum, physical RAM fault mapping, real hardware service diagnostics, interrupt-cycle timing, and PIA/LED operations remain untranslated; see docs/STAGE56_ROM_BOOT_SOURCE_AUDIT.md. Stage 54 – Enter/Return can be bound to Fire: Keyboard Controls accepts Enter or Numpad Enter for FIRE only. During gameplay it becomes the same logical KeyF cabinet input as any other configured Fire key. On the attract screen Enter still starts a game, and in the Hall of Fame it confirms initials. The original game/sound routines and key defaults are unchanged.

Stage 53 – high-score entry and corrected THRUST: Approved filtered-noise fix now runs through the game's original VSNDRM1 FNOISE sound-board path, including ADCA/SBCA high-byte overflow and borrow flags. After the original GAME OVER, the source waits 40 ticks, then HALLOF checks the player's packed-BCD score against the eighth score, presents original HOF initials/underline effects and permits UP/DOWN/FIRE selection. Qualifying scores are inserted into today's and all-time lists and the correct original organ cue is played; all-time records are saved using browser-local storage as a CMOS adapter. On each fresh page load, today's records use the original ROM factory table (ROMC8.RHSTDS). Use the Test Hall of Fame entry diagnostic button to check the screen without finishing a game. Full MESS0 cursor control interpretation and hardware CMOS remain unverified. See docs/STAGE52_HIGH_SCORE_AND_THRUST_AUDIT.md.

Stage 51 IRQ/TIMER timing: The physical video clock now increments the original eight-bit TIMER independently of the executive. When a source graphics pass overruns one or more video periods, EXEC0 consumes the accumulated timer ticks in one process-dispatch pass, rather than replaying a fictional queue of passes. Browser paint rate no longer throttles the nominal video IRQ to one tick per rendered frame. The original $30, $2E and $28 sleeps remain unchanged. The graphics cycle ledger is still partial, and the first complete title redraw remains at video frame 338 in the deterministic source harness; this is not yet a cabinet-verified animation speed. See docs/STAGE51_DEEP_TIMING_AUDIT.md.

Stage 43 source corrections: In the original attract demonstration, LEDRET starts CBOMB; the translated colour process now runs and cycles MUTANT palette slot C during both source APVCT appearances. The original BLK71.BGOUT writer now restores terrain after SAMEX explosions erase video bytes. The WILLIAMS title uses its own LOGO0/LGOTAB source-traced nibble positions for presentation restoration during DEFENDER appearance; no new artwork was created. Browser task interleaving is not yet cycle-exact. See docs/STAGE43_LOGO_MUTANT_TERRAIN_AUDIT.md and the regression tests.

Original video pipeline, resistor-weighted colours, source-cycle Bomber/mine colours and visibly twinkling stars. Enemy waves, movement, collisions, astronaut captures and rescues, lasers, Reverse, player deaths, explosions, and wave transitions use named assembly-derived routines. Original inter-wave bonus messages now appear inside video RAM and award each surviving astronaut 100 points times the completed wave number (capped at ×5), one every four update ticks, before the 128-tick next-wave pause. The first wave starts with five of fifteen Landers and no Baiters or Swarmers. Original-score NUMBR0–NUMBR9 glyphs, spare-ship and Smart Bomb icons are drawn by CWRIT into the game framebuffer. The Williams 16-entry colour RAM is updated through the original IRQ path, with the original Williams resistor-weighted 3:3:2 DAC conversion; the COLR process now cycles the laser colour. The original HYPER/HYP02/HYP2 hyperspace process is available (H key or button), and holding FIRE triggers repeat requests through LFIRE with an explicit browser-only repeat interval. The browser nominal frame cadence uses the board's 1 MHz / 16,640-count video period (approximately 60.096 Hz).

Stage 42 scanner fixes: The existing source DEFA7.BORDER now creates the blue radar enclosure; SCINIT and LEDRET restore the original $DB then $D9 STATUS sequence so SCNR.MT1 draws the real BLK71 miniature terrain. Original scanner marker $1030 is no longer overwritten by demo-ship movement, and source CREDS renders cabinet credits only if present. See the source audit for remaining unverified scheduling boundaries.

Stage 42 attract mode: The machine now boots into an animated, source-derived Williams/Defender presentation and a scripted rescue/enemy demonstration from the original AMODE1.SRC. The Williams line art uses LGOTAB/LOGO0 bytes and the source COLR/TIECOL palette processes. The ELECV/PRES1 original presentation lettering uses the exact $3258/$3E6C MESS0 cursor instructions and is refreshed after title expansion, protecting intact ELECTRONICS INC. and PRESENTS text. Source AMODE3/AMOD11 shot sequences now call XSVCT/EXST/EXPU/EWRITE, creating the original Lander and six enemy explosions. Source APST/EXPU also restores each enemy materialisation before its sprite appears; TEXTP follows the original captions and point values in TEXTAB order. The animated DEFENDER title now uses 15 original DEFENS/APST/EXPU/DEF50 appearance objects before restoring the full DEFDAT/DEFNNN bitmap, and the demo uses original object bitmaps and timed LEDRET/AMODE1–8/AMOD12 stages. Press ENTER or tap START GAME to play; WATCH DEMO returns to attract mode. The original ROMC8.DEFALT high scores initialise both columns. Source-derived high-score initials entry now updates the tables after qualifying games; all-time records are retained using browser-local storage. Cabinet coins and physical CMOS are not yet implemented. Sound-board DAC integration is now available in Stage 48.

Stage 35 bug fixes: A Smart Bomb that eliminates the final enemies now completes its original palette-flash phase before the wave-completed and astronaut-bonus display is drawn. The source wave executive still uses its normal 15-tick wakeups, and the inter-wave bonus text/score cadence is unchanged. A dying Bomber is now erased from the source framebuffer before its object record is unlinked, fixing a stale-sprite artifact after Smart Bomb use. The original sprite bitmaps, collision vectors, object lists and score routines are preserved. Unlimited Smart Bombs remain enabled for testing, and sound remains deferred.

Stage 34 display work retained: Original THPROC, TIECOL and CBOMB continue to run as source processes. Bomber palette phases now have RGB *sprite-pixel* regression coverage, and the browser uses the original board resistor weights rather than ideal 3:3:2 linear scaling. The translated star SBLNK colour branch is sampled every game update, where the source seed permits it, instead of at one-quarter speed: visible star brightness transitions are now checked in the final framebuffer. A further critical fix corrects presentFrame → framePixels: Stages 29–33 inadvertently discarded the hardware colour palette, displaying a fixed diagnostic colour table despite source colour cycling. The original assembly does not establish the normal-game SBLNK call cadence, so the host sampling rate remains provisional, not cabinet-verified. Deliberate development option: unlimited Smart Bomb ammunition is enabled for now; the original three-charge counter and icons remain in the source. Sound is now connected through DEFA7.SNDOUT. This is not yet a fully verified arcade-equivalent implementation: the initial hardware/raster inputs, complete EXEC/SINIT timing and analogue CRT gamma are still approximated or not implemented. The independent source workbenches below remain diagnostic fixtures, not the active game wave.

Scope and controls
Keyboard defaults: A up, Z down, RIGHT SHIFT thrust, SPACE reverse, TAB Smart Bomb, H Hyperspace, ENTER fire. Use KEYBOARD CONTROLS to reassign these, including Enter as Fire. The ship and thrust are written into video memory by native translations of the original POUT, ON86 and THOUT routines. The fixed-point movement uses PLAYER. Press T to test source terrain redraw, or B to test source SCNR object/player blip placement with original miniature terrain from BLK71.SRC. Press V to test original FBOUT, or E to call original OFSHIT on the diagnostic object. Press G (or Test SCORE +10) to apply original packed-BCD score arithmetic in the diagnostic; the original source score-digit glyphs are now rendered to framebuffer memory. Hold your configured FIRE key (Enter by default; F optional) or HOLD FIRE to repeatedly fire the source LASR/LASL laser, checking source picture-byte collisions and awarding original score values. The original VSNDRM1 sound board DAC output is integrated.
Still absent or not verified: cycle-exact original sound-board interrupt pre-emption (not yet verified), hardware-driven startup, and exact 6809 instruction/raster timing. Source TDISP/SCRTRN and original numeral/ship/bomb graphics now use ROMF8 CWRIT/COFF/BLKCLR; colour-RAM data is interpreted using the board's 3:3:2 DAC with no analogue CRT transfer curve. PRDISP now runs from the translated two-phase IRQ; only the raster input samples are diagnostic. No substitute gameplay has been added.
